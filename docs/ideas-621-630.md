# Post-600 candidate ideas, pass 3

These ten ideas were added on 2026-07-27 after an integration review of privacy decisions, archive visibility, lifecycle sidecars, destructive SQL, export evidence, backup truthfulness, and recovery behavior. They are evidence-backed candidates, not an expansion of the canonical 1-600 execution goal and not implementation claims. Evidence ids resolve through [repositories-research-100.md](repositories-research-100.md).

621. **Monotonic capture-disposition lattice** `[M]` - Model Skip, Mask, MemoryOnly, Ephemeral, and Normal as typed dispositions with an explicit strongest-wins join, then property-test every combination of OS hint, detector, source consent, and user rule. _Value: Adding a permissive rule can never accidentally weaken an intrinsic secret or platform privacy decision. Evidence: GH-055, GH-062, GH-099, S-08._
622. **Canonical active-recall repository scope** `[M]` - Route list, FTS, fingerprint, near-duplicate, suggestion, and semantic candidates through one parameterized repository scope for expiry, archive, sensitivity, and session visibility, with query-plan fixtures for each backend. _Value: A new recall path cannot silently forget one visibility predicate while existing paths remain correct. Evidence: GH-020, GH-046, GH-049, GH-099._
623. **Lifecycle-sidecar integrity census with repair preview** `[M]` - Extend doctor to count missing/orphan annotation and residency rows, explain impact, and preview a bounded repair that can recreate neutral annotations but never invent historical residency evidence. _Value: Corruption becomes visible and recoverable without turning unknown sync/export history into a false clean state. Evidence: GH-046, GH-053, GH-080, S-22._
624. **Cross-connection destructive-race harness** `[M]` - Add deterministic barriers between preview, eligibility check, and mutation while a second SQLite connection changes pin, collection, and legal-hold state; require every delete path either revalidate atomically or defer. _Value: Protection that changes during cleanup cannot be lost in a check-then-delete race. Evidence: GH-046, GH-048, GH-090, GH-099, S-22._
625. **Two-phase export externalization receipt** `[L]` - Prepare a bounded encrypted artifact, fsync and atomically publish it, then commit a receipt binding snapshot hash, schema, destination class, and residency transition; failed publication records no completed export. _Value: “Ever exported” describes an artifact that actually left the store, not a JSON string that may have died in memory. Evidence: GH-079, GH-080, GH-097, S-22._
626. **Restorable backup-freshness proof** `[L]` - Bind the freshness badge to a snapshot id, authenticated root hash, schema version, source generation, and the latest successful isolated restore drill rather than a mutable timestamp alone. _Value: A recent but unreadable or partial file cannot masquerade as a healthy backup. Evidence: GH-080, GH-081, GH-097._
627. **Crash-replay ledger for grace deletion** `[M]` - Give recoverable deletion an idempotency key and explicit prepared, committed, restored, and purged states, then inject faults at every SQLite/CAS/checkpoint boundary and replay safely on startup. _Value: A crash cannot leave both an undeletable live row and an ambiguous recovery record, or purge the only usable copy. Evidence: GH-046, GH-053, GH-081, S-22._
628. **Audited legal-hold state machine** `[M]` - Require bounded owner/reason metadata for create and release, append content-free hash-chained transitions, and make hard privacy-expiry precedence an explicit reviewed policy rather than an incidental SQL exception. _Value: Legal hold becomes explainable and tamper-evident without claiming compliance the product has not earned. Evidence: GH-059, GH-065, GH-080._
629. **Privacy-entrypoint conformance corpus** `[M]` - Run the same synthetic OTP, key, token, recovery-code, card, high-entropy, and benign-number cases through capture, import, edited text, rule simulation, and query history, asserting that no entrypoint chooses weaker handling. _Value: Refactoring one detector caller cannot create a privacy gap that unit tests for the detector itself miss. Evidence: GH-057, GH-058, GH-092, GH-099, S-07._
630. **Corruption-oriented SQL invariant fuzzer** `[L]` - Generate missing sidecars, malformed metadata, stale CAS references, interrupted transactions, and reordered maintenance calls, then exercise every read and mutation against oracles for no protected deletion, no hidden-item recall, and no unrecorded export. _Value: Fail-closed behavior is tested over adversarial database states instead of only hand-picked happy paths. Evidence: GH-046, GH-092, GH-093, GH-098, S-22._
