# Implementation batch 301-350

Reviewed and accepted on 2026-07-27. This ledger is the execution overlay for backlog items 301-350 in [ideas-301-400.md](ideas-301-400.md). It distinguishes resident behavior from bounded policy/store contracts and from native evidence that the current generic adapters cannot prove.

## Status vocabulary

| Status | Meaning |
|---|---|
| **Runtime** | Exercised by the current resident binary, popup, store, CLI, or repository automation. |
| **Foundation** | Implemented and tested as a bounded reusable contract, but not connected to the final user-facing surface. |
| **Adapted** | A narrower implementation preserves privacy, portability, or truthful capability reporting. |
| **Native required** | Completion depends on real per-OS APIs, clients, transports, credentials, or assistive-technology evidence. |
| **Rejected** | The proposed mechanism conflicts with a safety or correctness constraint; its replacement is recorded. |

## Acceptance gate

Accepted on 2026-07-27 after all three review rows were resolved. `cargo fmt --all -- --check`, strict all-target/all-feature clippy, locked workspace and no-default-feature tests, the WASM target, release performance budgets, dependency deny/audit/vet, fuzz-target compilation, documentation contracts, workflow syntax parsing, and `git diff --check` passed. A Rust 1.97.0 Linux container with Mesa software Vulkan reproduced all 24 popup goldens without update mode and passed the accessible Actions-menu test. The 49-test root suite also passed outside the restricted sandbox, including Unix-domain-socket recovery and the Windows loopback fallback.

Native portal/menu-bar/notification-area/permission evidence, user-facing archive/restore/rule/search-memory surfaces, SQLCipher, and OS-keystore crash keys remain separate product gates; this deterministic acceptance does not claim those external proofs.
